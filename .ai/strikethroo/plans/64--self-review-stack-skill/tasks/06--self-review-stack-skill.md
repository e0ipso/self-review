# Write the self-review-stack SKILL.md

## Objective
Write `.agents/skills/self-review-stack/SKILL.md`: a project-agnostic, harness-neutral procedure that resolves a diff, designs and builds a stack with `scripts/stack.cjs`, checks each step, generates a guide per step through `self-review-guide`/`self-review-critique`, opens each step in `self-review-serve` or the desktop app, and summarizes.

## Skills Required
- `agent-skill-authoring`: writing a `SKILL.md` that matches the sibling skills' structure and voice.

## Acceptance Criteria
- [ ] Frontmatter: `name: self-review-stack`, a one-line `description`, and `metadata.argument-hint: "[git-diff-args... | pr-or-mr-url]"` (matching the siblings).
- [ ] Hard rules preserved from the source skill: never change the working tree, index or an existing branch; reproduce the diff exactly; a step builds only on itself and earlier steps; describe, never judge; local only.
- [ ] Every helper call is `node <skill-dir>/scripts/stack.cjs <subcommand> …` (no Python).
- [ ] Prefix rule: short form of the branch name plus `-stack`; a ticket key (`[A-Z][A-Z0-9]+-\d+`) only when the branch has one; `pr-<N>-stack` / `mr-<N>-stack` for a URL. Never overwrite an existing prefix; ask.
- [ ] Output directory is always `$(git rev-parse --git-common-dir)/self-review/<prefix>/`; every launch runs from the repository root with `-o <outdir>/<slug>.review.xml`; the skill explains why (git refuses to run inside `.git/`).
- [ ] Guides are generated by invoking `../self-review-guide/SKILL.md` (or `../self-review-critique/SKILL.md` for pre-seeded comments) with the step's diff args and the inputs task 2 documented (guide: output path `<outdir>/<slug>.review.guide.xml` and content ref `<step-branch>`; critique: review output `<outdir>/<slug>.review.xml` and content ref). No informal overrides of their steps.
- [ ] Serve mode: one `self-review-serve -o … <step diff args>` per step, started in the background portably (e.g. `nohup … > <outdir>/<slug>.serve.log 2>&1 &`, or the harness's background mode when available), with `npx @self-review/serve` as the fallback when `self-review-serve` is not on PATH; `--resume-from <outdir>/<slug>.review.xml` when critique pre-seeded comments; ends with `stack.cjs table`.
- [ ] Desktop mode: `self-review -o <outdir>/<slug>.review.xml <step diff args>` one step at a time, waiting for each to finish before the next.
- [ ] Sequential by default; subagents and background tooling described only as optional optimizations.
- [ ] Step check: the project's type checker or build in a temporary worktree of each step branch (`git worktree add --detach <tmp> <step-branch>`, removed afterwards) is primary; `stack.cjs check-imports` is an optional JS/TS extra with aliases from tsconfig `paths`; one framework (SvelteKit) appears only as a labeled example. The summary states which check ran.
- [ ] No `ignore` generation and no "Loaded N files" check; when `git ls-files --others --exclude-standard` is non-empty, tell the reviewer each step will list those files as new and "Hide New Files" hides them.
- [ ] Stops when `~/.config/self-review/config.yaml` sets `guide-file`.
- [ ] Summary covers the table, the reproduced diff and base, departures from plan-document order, which check ran, local/unpushed branches, that `self-review-apply` acts where the original diff ends, a temporary clone's path for URL sources, and cleanup commands.
- [ ] `grep -nE 'EA-485|Strikethroo|port forwarding|python' .agents/skills/self-review-stack/SKILL.md` finds nothing; `grep -n SvelteKit` finds only the labeled example.
